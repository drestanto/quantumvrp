# 6_quantum vrp_initial_approach/

This directory contains the initial successful implementation of a Quantum Approximate Optimization Algorithm (QAOA) for solving the Vehicle Routing Problem (VRP). It demonstrates the core workflow, from setting up IBM Quantum credentials and a basic circuit test to running a QAOA-based VRP solver and interpreting its results.

---

## Contents

* `quantum_api_test.py`:
    * **Purpose**: This script serves as a foundational test for connecting to the IBM Quantum platform. It verifies that your IBM Quantum API token is correctly configured and that you can successfully initialize the `QiskitRuntimeService`, select a backend (real device or simulator), create a simple quantum circuit (e.g., a Bell state), transpile it, run it on the Sampler primitive, and retrieve measurement results.
    * **Usage**: Run this script first to ensure your environment is set up correctly before attempting more complex QAOA implementations. You will need to replace the placeholder `my_token` with your actual IBM Quantum API key.
        ```bash
        python quantum_api_test.py
        ```

* `quantum_vrp.py`:
    * **Purpose**: This is the main script that implements the QAOA for a specific VRP instance. It loads a pre-computed distance matrix for a selected cluster (from `cluster_complete_graphs.json`), allocates qubits using a "Node-Visit-Time Encoding" scheme, constructs a parameterized QAOA circuit, and uses a classical optimizer (`scipy.optimize.minimize` with COBYLA) to find optimal QAOA parameters (gamma and beta). Finally, it runs the optimized circuit on the IBM Quantum Sampler to obtain the most probable bitstring, which is then decoded into an optimal VRP route and its total cost.
    * **Configuration**: Before running, you **must** edit the `cluster_type` and `target_id` variables within the script to specify which VRP cluster from `cluster_complete_graphs.json` you want to solve.
    * **Dependencies**: This script relies on `qiskit-ibm-runtime`, `qiskit`, `numpy`, and `scipy`.
    * **Usage**:
        ```bash
        python quantum_vrp.py
        ```
        Be aware that running on a real quantum backend might incur costs and queue times. The script is configured to fall back to `AerSimulator` if a real backend is unavailable or encounters issues.

* `sample.out`:
    * **Purpose**: This file contains a sample output log from a successful run of `quantum_vrp.py`. It demonstrates the typical console output, including:
        * VRP data loading and qubit allocation details.
        * Progress of the classical optimization (expected cost at each iteration).
        * The optimal QAOA parameters found.
        * The most probable bitstring obtained from the quantum sampler.
        * The decoded optimal VRP route and its calculated total cost.
        * A comparison with a `naive_vrp.py` (classical brute-force) solution for the same cluster, showing the difference in optimal path and distance.
    * **Usage**: Review this file to understand the expected output format and the information generated by `quantum_vrp.py`. It provides a concrete example of a quantum VRP solution for a small instance.

## Workflow

1.  **Preparation**: Ensure you have an IBM Quantum account and your API token is correctly configured (you can use `quantum_api_test.py` to verify this).
2.  **Input Data**: Make sure the `cluster_complete_graphs.json` file (from `3_clustered data/`) is present in this directory.
3.  **Test API Connection**: Run `python quantum_api_test.py` to confirm your setup.
4.  **Configure VRP Solver**: Open `quantum_vrp.py` and set the `cluster_type` and `target_id` for the VRP instance you wish to solve.
5.  **Run QAOA Solver**: Execute `python quantum_vrp.py`. Observe the output, which includes the optimization process and the final VRP route.
6.  **Review Sample Output**: Compare your script's output with `sample.out` to understand the different stages and results.

## Notes

* **Qubit Limitations**: Quantum computers are still in their early stages. The `quantum_vrp.py` script uses a "Node-Visit-Time Encoding" which helps manage qubit count, but the problem size (number of customers in a cluster) that can be practically solved is still limited by available quantum hardware.
* **Approximation**: QAOA is an *approximate* optimization algorithm. While it aims to find good solutions, it does not guarantee the absolute optimal solution, especially with a limited number of QAOA layers (`QAOA_P`) or optimization iterations.
* **Real Hardware vs. Simulator**: The script can run on real IBM Quantum devices (if available and configured) or a local simulator. For faster iteration and larger problem sizes (within simulator limits), using a simulator is often preferred during development.
